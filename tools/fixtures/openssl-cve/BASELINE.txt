CVE reproducer harness - baseline FAIL output
==========================================================================

Recorded by tools/openssl-cve-test.sh against the baseline:
openssl-port ref `cve-baseline` (1.0.1u + the 9 Android patches of the recipe,
before the first cve-* patch). On this ref every kept
CVE must reproduce (FAIL = vulnerable) and every benign control must be clean
(PASS). Re-create with (arch and --asm compose):

    tools/openssl-cve-test.sh --selftest                   # host (x86_64)
    tools/openssl-cve-test.sh --arm32 --selftest [--asm]   # armhf, qemu-user
    tools/openssl-cve-test.sh --x86   --selftest [--asm]   # i386, native
    tools/openssl-cve-test.sh --mips  --selftest [--asm]   # mipsel o32, qemu-user

All libraries are built in Docker (never host gcc): host = `kktls-aosp-build`
(Ubuntu 14.04 / gcc 4.8, libasan); arm32 = Debian sid crossbuild-essential-
armhf; x86 = Debian sid gcc-multilib (gcc -m32, lib32asan); mips = Debian
bookworm crossbuild-essential-mipsel (gcc 12, no libasan for mipsel).
Since 2026-10-13 every arch builds on debian:trixie (gcc 14; mipsel cross
gcc 14 still has no libasan); --selftest there passes in all 7 cells.
--asm = the asm modules AOSP 4.4 ships for the arch (openssl.config
OPENSSL_CRYPTO_SOURCES/_EXCLUDES/_DEFINES_<arch>, .S generated like
import_openssl.sh; byte-identical to the .S of the import):
arm32 7 modules, x86 16, mips 5 (bn-mips.S included). AOSP 4.4 builds no
x86_64 asm, so --asm needs an arch flag.

Failure class per CVE (fixtures/openssl-cve/<cve>/expect):
  hang  = decided by work done: the call returned with
          KKTLS_CVE_RESULT=accepted (did the unbounded work) or never returned
          within the expect timeout (safety bound) -> 2018-0732, 2022-0778,
          2023-2650; fixed = KKTLS_CVE_RESULT=rejected with the fix's error
  crash = attack dies on a signal (rc >128) -> 2018-0739 (SIGSEGV)
  asan  = AddressSanitizer report           -> 2024-5535 (SKIP on arm32/mips)
  mem   = peak RSS (ru_maxrss) >= rss_kb     -> 2026-35189 (threshold 60000 KB)
  kat   = known-answer test: wrong vs correct against a hard-coded expected
          value -> 2021-4160 (only under --mips --asm; SKIP elsewhere)

2023-3446 / 2021-4160 rows: added to each block
from a restricted run `--selftest 2023-3446 2021-4160` (same cve-baseline
(debian:trixie images); the block headers above them still list
the 6 original CVEs of the full re-record. 2021-4160 is a SKIP row everywhere
except mips+asm. Patched ref u-android c32541c: ALL PASS in
all 7 cells.

2020-1971 rows added to each
block from a restricted run `--selftest 2020-1971` (same cve-baseline). The kat
reproduces the template part only (EDIPartyName explicit tags, aa0ad2011d):
the RFC 5280 DER of an API-built EDIPartyName is not produced (encode:differ)
and not read back (decode:fail) on the baseline. Patched ref u-android
a4b203b: PASS in all 7 cells, `--target` COMPILED.

Every run.c prints KKTLS_CVE_CALL=<fn> before and KKTLS_CVE_REACHED=<fn> after the
call under test (cve_common.h); hang/kat also print KKTLS_CVE_RESULT=<word> <detail>.
A hang/crash verdict needs CALL without REACHED (or, hang only, REACHED +
accepted), a PASS needs rc 0 + REACHED (+ the class's fixed result word / a
valid RSS for mem), a control needs rc 0 + REACHED (+ accepted for hang);
anything else is ERROR / BAD.

Note the hang rows that read "did the unbounded work": the vulnerable
OBJ_obj2txt finished inside the timeout (x86 9 s < 10 s, mips+asm 35 s < 40 s).
The pre-7a rule (rc 0 -> fixed) reported those as PASS - the same false PASS
the Mac/Rosetta benchmark hit (commit 821623d3).

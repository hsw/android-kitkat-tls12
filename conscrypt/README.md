# Layer D: standalone Conscrypt 2.6-alpha2 for Android 4.1.2 to 4.4

Layer D adds TLS 1.3 (and TLS 1.0–1.2 with ChaCha20-Poly1305 and X25519) to the default `SSLSocketFactory` of an
Android 4.4, 4.3, 4.2 or 4.1.2 system that already has layer A (the java zip of the same release). It is the published
`org.conscrypt:conscrypt-android:2.6-alpha2` artefact (Maven Central; BoringSSL inside), turned into system modules:

| Module | Installed as | From |
|---|---|---|
| `kktls-conscrypt` | `/system/framework/kktls-conscrypt.jar` | the aar's `classes.jar`, JNI library name changed, dexed by d8 (Jelly Bean: `StandardCharsets` replaced, `--min-api 16`) |
| `libkktls_conscrypt_jni` | `/system/lib/libkktls_conscrypt_jni.so` | the aar's `armeabi-v7a` or `x86` JNI library, byte-identical (4.2 ARM and 4.1: one `.dynamic` entry edited, see below) |
| `kktls-sslfilter` | `/system/framework/kktls-sslfilter.jar` | `sslfilter/`: drops SSLv3 and the weak suites on Conscrypt sockets |
| `libkktls_compat` | `/system/lib/libkktls_compat.so` (4.2 ARM, 4.1 ARM and x86 only) | `compat/`: the bionic functions the JNI library imports and that base lacks |

None of them is on the boot class path and nothing changes in the ramdisk. The default factory
`io.github.hsw.kktls.KktlsDefaultSSLSocketFactory` is part of `core.jar` (libcore patch 0025 on 4.4, also in
`core-libart.jar`; patch 0033 of each `patches/jb/<ver>/libcore/` series, the same source). On first use it loads the
two jars and the `.so` with its own class loader when `kktls-conscrypt.jar` exists, and falls back to the platform
factory when the files are absent or fail to load. Before that it checks the ELF headers of the `.so` (and of
`libkktls_compat.so` where it exists) and, for the ARM library, that the CPU has NEON (`AT_HWCAP` from
`/proc/self/auxv`, else the `Features` line of `/proc/cpuinfo`): the aar's ARM library is built with NEON as its
baseline and would die with SIGILL in the linker. On Jelly Bean it takes the inner
`org.conscrypt.OpenSSLSocketFactoryImpl` of the adapter that Conscrypt's `SSLContext` returns below API 22 (the
adapter's sockets extend a 4.4-only class), and its platform factory is harmony's `OpenSSLSocketFactoryImpl`. The system
property `persist.kktls.conscrypt=0` turns layer D off. See the top-level README for the scope and the behaviour
changes.

## Why the JNI library is renamed

The 4.1 to 4.4 dynamic linkers identify a library by its basename. An app that bundles its own Conscrypt loads
`libconscrypt_jni.so`; if ours had the same name, the app would get our already loaded copy, and its `JNI_OnLoad` would
bind to the wrong class loader's classes. `rename_jni.py` changes the library name inside the jar's `NativeCrypto`
class, so the system copy loads `libkktls_conscrypt_jni.so` and both can coexist.

## Building the stage

The 2.6-alpha2 classes are Java 8 class files that the 4.4 `dx` refuses, so the jar is dexed outside the tree:

```
python3 -I conscrypt/mkstage.py conscrypt-android-2.6-alpha2.aar STAGE/2.6-alpha2 \
    --java-libs <built 4.4 tree>/out/target/common/obj/JAVA_LIBRARIES --d8 <build-tools 37.0.0>/d8
python3 -I conscrypt/check_prebuilt.py --stage STAGE/2.6-alpha2
```

- `mkstage.py` checks the aar and every intermediate against `SHA256SUMS`, runs `rename_jni.py`, then
  `d8 --release --min-api 19`, and writes `kktls-conscrypt.dex.jar`, `libkktls_conscrypt_jni.so` and
  `x86/libkktls_conscrypt_jni.so`. d8 from Android build-tools 37.0.0 gives the pinned bytes; another d8 version fails
  the pin with both hashes shown.
- `check_prebuilt.py --stage` checks the pins, the dex format, the ELF headers of both ABIs, that the `.so` imports only
  symbols the 4.4 bionic exports (`bionic44-exports.txt`, `bionic44-exports-x86.txt`), and the `NOTICE`.
- `Android.mk` installs the stage files byte-identical (sha256-checked in the build recipe). The stage directory is
  `KKTLS_CONSCRYPT_STAGE` (default `../stock/conscrypt/2.6-alpha2/` beside the source tree).

`tools/kktls-release-build.sh` does all of this; see its header.

### Jelly Bean stage (Android 4.1-4.3)

```
python3 -I conscrypt/mkstage.py conscrypt-android-2.6-alpha2.aar STAGE/2.6-alpha2-jb --jb \
    --java-libs <built JB tree>/out/target/common/obj/JAVA_LIBRARIES --d8 <build-tools 37.0.0>/d8
python3 -I conscrypt/check_prebuilt.py --stage STAGE/2.6-alpha2-jb --jb --base 4.3
```

- After `rename_jni.py`, `jb_charsets.py` replaces `java.nio.charset.StandardCharsets` (API 19; d8 does not backport
  it, and Conscrypt reads it on the ALPN, keying-material, PSK and scrypt paths) with an own
  `org.conscrypt.KktlsStandardCharsets` (`US_ASCII`, `UTF_8` from `Charset.forName`), generated byte for byte by the
  script; then `d8 --release --min-api 16 --lib core`. The output (`2.6-alpha2/jb_charsets:classes.jar`,
  `2.6-alpha2/jb/kktls-conscrypt.dex.jar`) is pinned in `SHA256SUMS`, and is the same with the 4.1, 4.2 and 4.3 core jar.
  The `.so` files are the pinned aar files; 4.3 resolves every import.
- 4.1 and 4.2 lack some bionic functions the `.so` imports (4.2 ARM `getauxval`; 4.1 ARM `getauxval` and
  `__memcpy_chk __memmove_chk __memset_chk __open_2 __strlen_chk __vsnprintf_chk`, 4.1 x86 those six). `compat/` builds
  `libkktls_compat.so` in the base's own AOSP tree with exactly the missing functions of that base and ABI
  (`getauxval` reads `/proc/self/auxv`, and where a non-dumpable process cannot open it, as in every app of a user build,
  takes `AT_HWCAP`/`AT_HWCAP2` from the `Features` line of `/proc/cpuinfo`; the fortify functions check and abort as
  bionic 4.2 does), and `jb_needed.py`
  turns the `.so`'s `DT_SONAME` entry into `DT_NEEDED libkktls_compat.so` (the JB linkers ignore `DT_SONAME`; `.dynamic`
  has no free entry). The new entry is the last one, and both JB linkers search `DT_NEEDED` in order, so libc and the
  other system libraries always come first. `mkstage.py --jb` writes the edited files to `jb-compat/` (one per ABI, for
  4.1 and 4.2); the edited files and each base's compat library are pinned in `SHA256SUMS`. 4.2 x86 and 4.3 keep the aar
  file. `check_prebuilt.py --stage DIR --jb --base 4.1 --compat FILE --compat-x86 FILE` checks that the edited `.so`
  resolves against that bionic plus the compat library and that the library exports exactly what is missing.
- `tools/kktls-jb-openssl-build.sh` stages it for a base with a `conscrypt` or `compat` line in
  `patches/jb/targets.txt` (the `stage` step; a `compat` base also builds the compat library) and ships
  `kktls-conscrypt-<base>-<abi>` zips through `tools/mkzips.sh --jb`. Where a `conscrypt` base and ABI need the compat
  library (4.2 ARM, 4.1 ARM and x86), the zip carries the `jb-compat/` `.so` and `lib/libkktls_compat.so` as a fourth
  file; the installer's restore removes it with the other three, and the default factory checks its ELF header as it
  does the `.so`'s when the file exists.

## Checks and tests

- `python3 -I conscrypt/apicheck.py --selftest`: the Java API the dex references, against what Android 4.4 provides
  (`apicheck-allow.txt` lists the reviewed exceptions).
- `python3 -I conscrypt/rename_jni.py --selftest`, `python3 -I conscrypt/jb_charsets.py --selftest`,
  `python3 -I conscrypt/jb_needed.py --selftest`, `conscrypt/compat/test/run-host-tests.sh` (the compat functions on
  fake auxv and cpuinfo files and the host's own auxv, the fortify aborts),
  `python3 -I conscrypt/check_prebuilt.py --selftest AAR`, `check_prebuilt.py --selftest --stage DIR [--jb-dexjar FILE]`.
- Jelly Bean: `check_prebuilt.py --stage DIR --base 4.3|4.2|4.1` checks the `.so` imports against the bionic of
  our own AOSP 4.3/4.2.2/4.1.2 builds (`bionic4[123]-exports{,-x86}.txt`); `--selftest --stage` asserts what each base
  lacks (4.2 ARM `getauxval`, 4.1 the fortify functions and, on ARM, `getauxval`). `apicheck.py --api 16|17|18` with
  that base's `core` and `framework` jars checks a `d8 --min-api 16` dex (`apicheck-allow-jb.txt` lists the reviewed
  Jelly Bean exceptions).
- `conscrypt/sslfactory/test/run-host-tests.sh`: the default factory and the SSLv3 filter on a host JVM with stubs
  (files present, absent, broken; the kill switch; NEON from fake auxv and cpuinfo files; the Jelly Bean platform
  factory and inner factory). It first checks that the 4.4 and Jelly Bean libcore patches carry this source byte for
  byte.

## Licences

`NOTICE` holds the Conscrypt and BoringSSL licence texts of the pinned versions. `mknotice.sh` regenerates it from a
Conscrypt clone and the BoringSSL commit named in the aar; its sha256 is pinned in `SHA256SUMS`.
